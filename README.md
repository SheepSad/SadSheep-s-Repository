# 2048 + 自动操作 AI程序

两个文件，零第三方依赖：

| 文件 | 说明 |
| --- | --- |
| `2048.html` | 2048 游戏本体（拥有深色/浅色主题，合成动画、实时计分、历史战绩记录等） |
| `play2048-ai.mjs` | 用 expectimax AI 自动操作这个游戏，输了自动重开，直到赢下 2048 |

## 快速开始

```bash
node play2048-ai.mjs              # 打开 2048.html，AI 自动玩到 2048 获胜（无头浏览器）
node play2048-ai.mjs --head       # 想亲眼看它玩就加这个，会弹出浏览器窗口
node play2048-ai.mjs --head --every 75   # 实时围观，同时每 75 秒抓一张过程图到 ai-shots/
node play2048-ai.mjs --fast       # 加速模式，压缩动画等待
node play2048-ai.mjs --sim        # 不开浏览器，直接执行页面脚本（CI / 沙箱环境可用）
node play2048-ai.mjs --bench 20   # 纯自我对弈 20 局，输出胜率与平均得分
node play2048-ai.mjs --selftest   # 校验 AI 的走子规则与游戏内实现完全一致
node play2048-ai.mjs --help       # 全部参数
```

只想玩的话，直接双击 `2048.html` 即可，不需要 Node。

## AI游玩逻辑

1. **启动浏览器**：自动探测 Edge / Chrome，用 `--remote-debugging-port` 打开游戏页；
   启动方式会按「现代无头 → 旧版无头+单进程 → 无头+单进程 → 关闭沙箱」依次重试，
   以适配禁止创建命名管道、导致 Chromium 多进程 IPC 崩溃的受限环境。
2. **读棋盘**：从 DOM 里读每个 `.tile` 的 `--x` / `--y` 与文本值，还原成 4×4 棋盘。
3. **思考**：expectimax 搜索。玩家节点取最大期望，机会节点枚举“在哪个空格生成 2 还是 4”
   并按 0.9 / 0.1 概率加权。棋盘用指数编码（0=空，11=2048），行合并结果用 65536 项的
   查找表预计算，搜索全程零内存分配。
4. **操作**：用 `Input.dispatchKeyEvent` 发送真实方向键事件，和真人按键走的是同一套逻辑。
5. **直到胜利**：出现 2048 就结束并截图；若这局走死就自动重开，默认最多尝试 20 局。

## 棋力调节方式

```bash
node play2048-ai.mjs --depth 4              # 搜得更深，更强也更慢
AI_W_MERGES=0 AI_ADAPTIVE=0 node play2048-ai.mjs --bench 10   # 消融实验
```

## 实测结果

在本机（Edge，实时模式）环境下运行默认配置：

| 场次 | 结果 | 步数 | 得分 |
| --- | --- | --- | --- |
| 无头浏览器 | 第 1 局获胜 | 953 | 20196 |
| 弹窗演示 `--head` | 第 1 局失败（最大 1024）→ 第 2 局获胜 | 955 / 1015 | 16148 / 20516 |
| `--sim` 无浏览器 | 第 1 局获胜 | 967 | 20304 |

单局胜率不是 100%（这是 expectimax 的固有方差），所以程序内置了失败重开。

只要单局胜率大于 0，连续 N 局都失败的概率会指数衰减，默认 20 局足够稳。

上面那次演示正好跑出了完整的「失败 → 自动重开 → 获胜」流程。

## PS

- `--sim` 模式不重新实现游戏，而是把 `2048.html` 里那段 `<script>` 原样取出、
  装进一个最小 DOM 里执行，再通过它自己的 `keydown` 监听器“按键”。
  跑的就是页面里那份真实逻辑，只是没有渲染。
- 游戏里的 `isGameOver()` 原本会在棋盘没满时抛异常（`g[y][x+1]` 可能是 `null`）。
  浏览器里这个异常被定时器回调吞掉了所以不易察觉，但确实每次移动都在报错。
  已修复为「先判空再取值」。
